# 截屏释义 v0.8.2 — 三模式运行状态与均衡布局

## 主界面运行状态

用真正的 Avalonia 控件替换原来的“轻量模式可用”单一状态条。现在同时显示 **轻量模式、基础模式、云端模式** 三张卡片，以及 **刷新状态** 和 **查看详情**。

绿色表示本地可用或已配置、按需加载；红色表示未配置或需要处理；灰色表示尚未检测或待验证。状态文字与指示灯同步，不只靠颜色区分。当前选择的处理方案与三种模式各自的状态分别显示，不再以轻量模式可用代替基础模式状态。

## 修正上方拥挤、下方空白

增大状态区上下留白与标题/卡片间距，模式卡片最低高度为72个逻辑像素，图标、名称及状态标签垂直居中。主页根据可用窗口高度重新分配截图区、处理流程和状态区的空间，避免状态区压成一条窄条、其下留下大片空白。

默认窗口仍为1040×720，不缩小字体。较高窗口利用新增空间；较窄/较矮窗口保留可读的自然高度并允许滚动。底部“退出并释放资源”仍固定显示，错误修复区保持可访问。

## 设置中的运行状态详情

设置侧栏新增 **运行状态** 页面。主页“查看详情”打开或复用该页，显示模式原因、已配置/已安装/实际运行的区别，以及后端、模型与执行信息。原五类设置、未保存输入、所有手动任务、快捷键故障提示和退出清理逻辑保留。

## 状态检测与隐私边界

刷新不下载、不启动视觉模型、不进行额外推理，不更改处理方案。托管模型的被动检查只检查本地文件存在性、大小及已安装后端；完整校验仍在启动时执行。尚未加载的有效托管模型显示“按需加载”，不冒充已经运行。

外部本机服务仅探测回环地址；模型列表可达不等于视觉能力已验证。云端只读取安全存储中的配置存在性，不显示或记录凭据，不自动联网验证密钥、额度和连通性；未验证配置显示“待验证”。不会把尚未探测的下载服务或仅选中的显卡显示为已验证正常。

## 升级与分发

本次不改变安装身份、配置/模型目录、Vulkan默认后端或手动切换/卸载规则，也不删除旧模型或凭据。升级前请从托盘选择“退出并释放资源”，再安装新版。主窗口右上角×仍为隐藏到托盘；既有Windows安装前待重启检查不绕过。

提供Windows x64安装程序/便携ZIP和Linux x64 DEB/tar.gz，共四个程序包，附SHA256SUMS.txt。旧版标签和附件保留。

## 验证范围

自动化覆盖三模式判断、状态颜色、刷新与详情交互、配置草稿保留、中英文/浅深色布局、默认窗口完整可见性、较高窗口空白控制、缩小后滚动与恢复、错误修复区可访问性，并执行原有Windows/Ubuntu构建、.NET/Python及Linux虚拟桌面回归。

UI快照使用明确标注的合成状态，不是生成式效果图，也不冒充用户设备、云端服务或真实模型推理验收。本次不新增物理CUDA/ROCm、多显卡、显存回收或所有GNOME/Wayland组合的实机认证。

## English

Home now shows three live mode cards: Lightweight, Basic and Cloud, with Refresh and View details. The native status panel has taller cards and more breathing room. Spare viewport height is shared across the capture, pipeline and status sections instead of leaving a blank area above the fixed footer. The default window and font sizes are unchanged; small windows scroll without compressing text.

Settings adds a Runtime status page while retaining unsaved form input. Passive checks do not start a vision model, run inference, download files or contact cloud services. Configured-but-unverified services remain unverified, and configured managed models may be on demand rather than running. Existing privacy, runtime-switching, installation and exit policies are preserved. Synthetic UI/desktop tests do not constitute physical GPU or cloud-service certification.
