# 截屏释义 v0.8.4 — OpenAI Responses API 与第三方模型发现

## OpenAI Responses API

- OpenAI 服务商预设默认使用 Responses API（`POST /v1/responses`）。
- 文字翻译使用 Responses `instructions` / `input` 请求结构。
- 视觉 OCR、图片描述和提示词反推使用 `input_image`，支持 Base64 data URL。
- Responses 请求显式设置 `store: false`，不将本软件请求保存为 Responses 历史记录。
- 可在设置中手动切换 Responses API 与 Chat Completions。

## 保留 Chat Completions 兼容性

- DeepSeek、SiliconFlow、OpenRouter、阿里云百炼 / DashScope、智谱 BigModel 继续默认使用 Chat Completions。
- 本机 llama.cpp、Ollama、LM Studio 回环服务继续使用 Chat Completions；切回本机地址时自动恢复。
- 旧版本中使用官方 OpenAI endpoint 的设置会迁移到 Responses 默认；当前版本明确选择的协议会保留。
- 其他 OpenAI Chat Completions 兼容服务仍可手动配置。Responses API 不会被假定为所有兼容服务都支持。

## 第三方 API 设置改进

- API 模式自动关闭本地服务预设，回到本机回环端点后重新启用。
- 模型名称支持通过当前 API Key 刷新并选择服务商返回的模型列表。
- 模型列表获取失败或服务商不开放列表接口时，仍可手动输入模型 ID。
- 保留 API Key 系统安全存储、远程 HTTPS 要求和 URL 凭据拒绝规则。

## 隐私与计费

- 远程翻译会将识别文本发送给所选服务商。
- 远程 OCR、图片描述和提示词反推会将用户选中的截图发送给服务商。
- Responses 请求设置 `store:false`，但这不代表服务商不会根据其自身政策处理网络请求、日志或计费数据；请查看服务商当前数据政策。
- API Key 仍由系统安全存储管理，不写入 settings.json 或应用日志。

## 测试边界

Windows 与 Ubuntu 自动化构建和测试通过，覆盖 Responses 文本请求、视觉输入、输出解析、协议迁移、服务商默认协议、本地 Chat Completions 回归及设置界面切换。未使用真实 OpenAI 账户密钥执行线上调用；模型访问权限、组织配额、实际费用与视觉质量仍取决于用户账户和所选模型。

## 升级

先从系统托盘选择“退出并释放资源”，再安装 v0.8.4。已有模型文件、显卡后端和配置目录保留。

## English

v0.8.4 adds OpenAI Responses API support for text translation and vision tasks (OCR, image description and prompt reconstruction). Responses requests set `store:false`. OpenAI defaults to Responses; other providers and local llama.cpp/Ollama/LM Studio continue to use Chat Completions. Users can switch protocols in settings. API model discovery populates an editable model picker and retains manual model ID entry when the provider does not expose a model list. Remote requests still send recognized text or selected screenshots to the configured provider and may incur charges. Windows and Ubuntu CI passed; live calls with a real OpenAI account were not performed.
