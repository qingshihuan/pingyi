# 屏译 PingYi v0.5.0

新增「描述图片」「反推提示词」，并修复本机 llama.cpp 启动过程中的探测超时误判。整合 PR #18，保留此前统一界面、中英文即时切换、多屏截图隔离、离线 OCR / 翻译和后台资源优化。没有更换生产模型、增加生产运行依赖或覆盖旧 Release。

## 新增：直接分析图片内容

主界面「开始截图」下方新增两个入口：

| 功能 | 用途 |
| --- | --- |
| 描述图片 | 框选图片后描述主体、动作、场景、构图、颜色、光线、风格和材质，不要求图片中有文字。 |
| 反推提示词 | 根据可见画面整理可复制的绘图参考提示词，并提示不确定的细节；不能恢复原始提示词、种子或生成参数。 |

图片分析直接调用已配置的多模态模型，不经过 OCR，也不把 OCR 空结果当成不能分析图片。结果窗口可以针对同一张截图切换描述、提示词反推和文字翻译，支持重试、取消等待及复制分析内容。输出语言跟随中文 / English 界面，界面语言切换不改写已有用户内容。

**需要支持 image_url 图片输入的视觉模型。** 完全版可使用已下载并配置的托管视觉模型；标准版和完全版均可连接兼容视觉接口。普通文字模型、PaddleOCR 和 Argos 不提供图片描述能力。软件不会因视觉模型不可用而擅自改用云端服务。

## 修复：llama.cpp 偶发启动超时

- 分离单次 2 秒状态探测超时与整个模型启动期限。短暂请求超时、503 加载中或暂时不可用会继续检查，不再立刻误报为「75 秒内未完成模型加载」。
- 同时检查服务健康状态与预期模型标识；仅列出模型不再等同于服务可执行请求。
- Vulkan 和 CPU 分别设置 3 / 5 分钟有界启动期限，整个共享启动操作最多 10 分钟，并提供加载阶段提示。自动模式按原有设置回退 CPU，明确选择 Vulkan 时不擅自回退。
- 已运行的自有模型短暂繁忙不再立刻被杀掉重载；切换后端前确认旧进程退出。用户取消不会被错误当成后端故障，不终止用户自己运行的外部模型服务。
- 单个截图任务取消会停止等待或当前请求；仍有上限的共享启动可能继续进行，以便后续请求复用。显存不足、驱动或模型加载失败仍会明确报错，不能由延长等待消除所有原因。
- 模型标准输出按固定大小分块读取，只保留有限的预定义错误分类，避免长行、图片请求或正文在诊断信息中驻留。

## 数据处理与资源限制

远程视觉接口与文字翻译的数据范围不同：它需要接收完整框选图片。**每次上传前均显示接收服务和模型并请求确认；拒绝则不发送。** 程序冻结并复核端点 / 模型配置，非本机回环地址必须 HTTPS，不跟随自动重定向，也不自动切换云端提供商。

图片字节、像素、边长和响应大小都有上限；分析图片长边最多 1600 像素，预处理放在后台线程。模型分析请求本身有 3 分钟期限，与模型启动等待分开。不会新增截图或分析历史，不记录正文和密钥。提示词与图片描述由模型生成，可能出现误判，请核对重要细节。

## English summary

PingYi v0.5.0 adds Describe Image and Reconstruct Prompt actions for screenshots, including images with no text. A vision-capable image_url-compatible model is required. Results can be copied or reprocessed from the same in-memory capture; reconstructed prompts are references for similar images, not recovery of original generation parameters. Remote image requests require explicit per-request confirmation and never silently fall back to cloud services.

The managed llama.cpp startup path now distinguishes transient readiness-probe timeouts from bounded overall startup, checks health plus the expected model, preserves cancellation, and avoids unnecessary restarts of temporarily busy owned processes. Windows and Ubuntu regression suites pass; real GPU/driver startup behavior and vision-model output quality still require hardware validation. Standard and Complete packages retain existing settings and are accompanied by SHA-256 checksums.
