# 显卡、运行后端与推理响应

## 使用入口

首次模型配置引导和 **设置 → 本地模型** 提供“显卡与运行后端”区域。检测读取本机设备，不访问网络。Windows 使用 NVIDIA 工具及 CIM，Linux 使用 NVIDIA 工具、DRM/sysfs 和可用的 lspci。缺失字段显示未知，不把 Windows 的 32 位 AdapterRAM 当成可靠的大显存数值。

“运行后端”可选自动、NVIDIA CUDA 12、NVIDIA CUDA 13、AMD ROCm/HIP、Vulkan、CPU。“执行显卡”来自所选运行后端的实际 `--list-devices`，显示设备名、后端编号与枚举时的总量／可用量。系统显卡清单不等于模型运行时清单；专用后端未安装时需先安装，才能列出其设备。

保存／应用后，启动参数使用该后端设备名和单卡模式，不按 Windows GPU 0／1 或屏幕顺序猜测。切换设备或后端先停止本应用持有的旧进程。显卡名称、编号、容量或枚举顺序出现可检测变化时要求重新选择；两块名称、容量完全相同的卡仍应在更换硬件／驱动后重新检测确认，不能用名字证明物理身份。自动选择优先非通用核显名称的可用设备，再参考可用内存；这不是性能基准排名，核显共享内存不代表独立显存。

手动选择后端或指定设备失败时不会静默换到另一块卡。全自动模式才依次尝试兼容候选、Vulkan、CPU，并显示实际运行后端、版本和设备。已经回退且健康的进程继续复用，不在每次截图重新尝试失败后端。用户独立启动的模型服务不由屏译改卡或终止。

## 兼容选择与最新版

NVIDIA 依据可读到的 compute capability 和驱动分支选择候选。CUDA 13 面向 Turing 及更新架构，低于 580 驱动不自动选择；驱动 580 只是 CUDA 13.x 次版本兼容候选，不保证 CUDA 13.4 的所有功能可用，新功能可能要求 R615。Windows CUDA 12.4 不用于 Blackwell；Linux 的可信回退清单为 CUDA 12.8。未知架构／驱动不凭型号字符串强行下载安装。AMD ROCm/HIP 必须通过实际设备检查，列出显卡仍不能代替真实模型推理验证。

只有用户点击下载安装／更新或模型首次配置才查询官方最新稳定版，解析其对应二进制构建，并要求完整的官方 SHA-256、大小和匹配平台的服务器／CUDA 依赖包。正常截图不联网检查版本，也不安装驱动或整套 SDK。

官方版本查询失败时使用内置可信清单 `b11146`（核对日期 2026-09-29，稳定版 v0.5.0 对应构建），界面明确标注回退清单，不冒充已确认的最新版。保留原安装包的 `b10227` Vulkan／CPU 作为离线基础；可手动更新它们。

## 下载安全和国内连接

默认只访问官方 GitHub。用户可勾选第三方备用源；连接或读数据长时间无响应后依次尝试显式自定义 HTTPS 前缀、ghfast.top、ghproxy.net。备用源仅用于传输公开运行包，不提供可信校验信息；不会向其发送截图、正文、API Key 或系统凭据。第三方服务的可达性可能变化，未承诺所有国内运营商均可连接。

下载支持受验证的 HTTP Range 续传；服务器忽略 Range 时重新开始。长度、范围或最终 SHA-256 不符不执行、不安装，完整损坏文件会移除。取消不等于失败换源；用户取消立即结束，保留可续传部分。官方 API 无法访问时仍可凭内置清单下载已知包；不是从第三方读取未知可执行文件的摘要。

每个运行包先在用户数据目录的独立 staging 中提取，阻止目录穿越、绝对路径、危险链接和超量解压。保存为版本化目录，不覆盖已加载的 DLL；验证 `--version` 和 GPU 枚举后原子更新运行包指针，前一元数据保存在 `previous.json`，旧文件保留。该启动检查不等于模型验证。模型引导继续执行固定合成 OCR／翻译检查，失败不标记配置成功。没有实现通用离线包导入器或显卡驱动升级器。

## 响应与资源

模型 OCR／翻译使用独立 HTTP 客户端，不继承普通请求的 30 秒总超时；连接保持短期限。主翻译阶段与离线回退分别有两分钟预算，用户取消不触发回退。回退仍受原语言支持范围约束，不用中英 Argos 假装支持其他语言。

翻译失败后，在相同截图会话、相同 OCR 源设置下重试可复用已识别原文；截图、OCR 模型／端点或源语言变化后重新识别，成功后的“重新处理”也重新识别。缓存只在内存中随截图会话释放，不增加历史文件或日志。

新下载后端使用其支持的 GPU 层数 auto 与单卡选择，旧内置后端继续使用兼容参数。基础模式仍是本机视觉 OCR → 本机模型翻译，不恢复视觉纠错，也不把延长等待称为推理加速。具体吞吐和首字时间仍需在真实设备上测量。

退出与子进程清理继续遵循 [运行后端退出](RUNTIME_SHUTDOWN.md)。释放的只是本软件持有进程的资源，不要求显卡总占用归零。

## 验证边界

自动化覆盖硬件文本解析、后端候选、设备清单变化、用户选择保持、可信摘要、换源／续传／取消、解压路径、推理超时及 OCR 重试缓存。界面截图使用明确标记的合成设备。真实 NVIDIA／AMD 多卡推理、显存回收和国内网络环境仍需实机验收，不把无 GPU 的 CI 当作显卡实测。
