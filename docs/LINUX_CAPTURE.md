# Linux 截图与快捷键

## 默认键、自定义与兼容

Linux X11 从 v0.5.2 起默认使用 `Ctrl+Shift+D`。在设置 → 外观与启动中可手动输入、录入按键或恢复默认，点击保存并应用后生效。

Schema 10 将旧 Linux 已知默认值迁移到新默认：schema 8 及以前的 `Ctrl+Alt+D`、schema 9 及以前的 `Ctrl+Alt+Shift+D`；其他组合和带有显式自定义标记的设置保留。旧配置没有记录某个旧默认值是否被用户手动选过，此类情况需要重新设置一次。Windows 的默认键不受影响。

Ubuntu/GNOME 官方常用系统快捷键表没有列出 `Ctrl+Shift+D`，但发行版、桌面扩展和用户绑定可能不同；不能保证所有 Linux 配置都无冲突。Chrome 的收藏全部标签页功能使用相同组合，全局截图绑定可能覆盖该应用操作。完整操作及官方资料见 [HOTKEYS.md](HOTKEYS.md)。

## X11 注册与回退

XGrabKey 是异步请求，必须在 XSync 后检查 BadAccess，不能把调用返回或线程启动视为成功。屏译只截获本连接的 GrabKey 错误，转发其他连接错误并恢复原错误处理器；失败释放部分抢占和显示连接，不退出程序。

Caps Lock 和实际 Num Lock 修饰映射均处理，重复启动不创建多余线程。录入期间释放屏译自己的绑定；结束或取消后恢复。保存时先校验组合并尝试绑定，再持久化配置；绑定冲突或设置写入失败时恢复原绑定，恢复失败也会保留错误提示。按钮截图不依赖全局快捷键注册成功。

## Wayland

截图使用公开 XDG Screenshot 门户：同一连接先订阅自己的 Request::Response，再请求 interactive 截图；不绕过授权，不读取 XWayland 假桌面。系统交互最长等待五分钟，独立于 X11 15 秒像素抓取期限。取消发送 Request.Close；用户取消正常退出，门户缺失或失败明确显示。

门户选择的像素直接进入处理流程，不再套用 X11 框选层或屏幕坐标。结果定位使用 (0,0) 起点，因为门户未返回全局屏幕坐标。

**本版本没有实现 GlobalShortcuts 门户。** 应用内只能保存首选快捷键，并提供可复制的当前版本截图命令。用户需要在桌面系统键盘设置中绑定同一组合；修改应用中的组合后也需同步修改系统绑定。屏译不会私自修改系统设置，不把保存首选项假报为全局绑定成功。首次 `--capture` 和已运行实例的命令转发均支持。

## 依赖和数据处理

Ubuntu GNOME 需要系统 `xdg-desktop-portal`、`xdg-desktop-portal-gnome`、GLib/GIO；其他桌面需匹配后端。不调用私有 GNOME Screenshot 接口，不通过 shell/Python 帮助脚本执行截图。

门户文件仅接受本地 URI，拒绝 HTTP 等 URI；限制文件大小和像素数。读取后只清理临时目录中的门户副本，不删除任意用户图片。系统保存到其他目录的文件仍由系统管理，不保证这些副本零留存。截图不会增加应用历史，也不会绕过图片上传前的确认。快捷键录入只处理当前录入窗口的按键，不添加后台键盘记录组件。

## 自动验证与边界

CI 在 Windows/Ubuntu 跑 Core/UI/Python 测试。额外在隔离的 `dbus-run-session` + Xvfb/Openbox 中执行真实 X11 冲突、回退后按键触发、录入释放/恢复、截图、配置保存和进程重启验证。GIO/D-Bus 往返连接测试私有模拟门户，验证提前 Response、图像返回、用户取消、服务失败、Request.Close 和恢复。

原生测试通过环境变量显式启用。模拟门户与 Xvfb 不能代替真实 GNOME/Wayland 系统授权界面、多屏混合 DPI 或不同显卡的物理桌面验收。发布包的干净系统依赖安装验证也不等于这些交互组合已经逐一验收。
