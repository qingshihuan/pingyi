# v0.4.0 后续：五项易用性修复

## 实现范围

1. 单一界面：`MainWindow` 是唯一截图入口；`SettingsWindow` 只处理配置。删除旧样式选择、经典窗口入口与 `AppSettings.InterfaceStyle`。Schema 8 读取旧 JSON 时忽略该字段，正常保存时不再写入；不重置其他设置或安全存储。
2. 截图隔离：在串行操作门内取得所有应用窗口，关闭下拉框、暂时隐藏原本可见的窗口，再排空 UI 队列并等待桌面呈现，然后抓取唯一桌面底图并创建各显示屏的框选层。Windows 暂时关闭自身窗口的过渡动画，Windows 10 2004+ 暂时设置捕获排除；恢复原生标志。成功、Esc、故障、任务取消统一恢复原窗口。退出时不重新显示窗口。原负坐标、跨屏和不同 DPI 的几何转换保留。
3. 语言切换：主窗口、设置、结果、框选层和新页面的静态文案引用相同的中英文动态资源。选择语言先保存，成功后更新资源和已打开窗口，失败则回退选择。设置中的其他输入框、未保存密钥和结果正文不重建、不翻译。既有动态状态消息保留原始 UI 文案用于切回中文；未知服务错误仍可能由提供商决定语言。
4. 方案卡片：名称、方法、用途与使用条件分别展示，允许换行、纵向滚动，底部操作固定。离线基础、兼容大模型翻译、视觉纠错、百度云、自定义组合严格对应现有提供商。不会因选择大模型方案覆盖已配置的远程地址或模型；数据范围按实际地址说明。自定义项只导航，不改变原组合。若目标语言不受新引擎支持，则切回自动目标。
5. 帮助页：主页删除隐私卡，增加帮助入口。帮助页从当前设置生成图片/文字数据去向，展示实际程序集版本、现有快捷键、使用方法及仓库链接；不伪造官网、发布时间、最新版本或额外功能。

## 状态可见性补充

实际渲染检查发现旧的状态着色代码未指定主题，从浅深色资源字典取到空画刷，使设置底部状态及部分结果提示不可见。现改用绑定到控件的动态资源，支持错误/正常状态切换及运行时浅深主题变化，不增加轮询或动画。

## 自动验证

```sh
dotnet test PingYi.slnx -c Release
python -m unittest discover -s scripts -p 'test_*.py'
python -m unittest discover -s engine_host -p 'test_*.py'
```

`UsabilityRegressionTests` 通过真实语言下拉事件测试持久化、所有打开窗口的控件刷新、中英往返、失败回滚、用户原文/译文与未保存字段保留；检查最小方案窗口、帮助数据范围、无重复样式控件，以及所有应用窗口在呈现屏障之前隐藏，在成功/异常/取消后恢复。`ProcessingModesTests` 检查实际路由及地址保留。结构检查保证两套语言键相同、动态文案有定义、无静态语言快照。

UI 预览均为 Headless/Skia 渲染，使用合成输入；这不是物理多显示器验证或真实模型推理结果。没有新增或替换已发布安装包。

## 必须在用户桌面复核的多屏清单

- 主界面位于主屏，设置/固定结果位于副屏；分别从按钮与全局热键发起框选。底图不能出现屏译窗口、下拉框或过渡残影。
- 主屏在右、副屏在左（负 X），以及副屏位于上方（负 Y）。
- 同缩放与混合缩放，例如 100% / 150%，以及不同刷新率组合。检查跨屏拖选的边界与最终图像位置。
- Esc、连续按快捷键替换操作、抓取失败和退出时检查窗口恢复；此前隐藏或最小化的窗口不应突然显示。
- Win10 早于 2004 的版本仍采用隐藏/等待流程，不能出现捕获排除退化造成的黑块。Ubuntu X11 用 UI 队列排空和短暂等待，不调用 Windows API。

DwmFlush 只是附加呈现屏障，不代表整个会话所有合成器已刷新。上述硬件组合、系统安全存储、真实模型和全局热键需要桌面验收；自动测试不能替代。
