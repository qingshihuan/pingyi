# 可靠性与校验内存优化

本次改动基于 `e5b0c52b7932d391fc8e47b352378b14da6704e3`，不改变默认离线路径，不新增第三方依赖，不改动 OCR 模型、截图实现或界面布局。这是源码变更说明，不代表已有安装包已经更新。

## 改动范围

| 模块 | 原问题 | 修改 |
| --- | --- | --- |
| Python 模型校验 | `Path.read_bytes()` 将整个模型读入内存；只用大小和修改时间判断缓存 | 复用 1 MiB 缓冲区分块哈希；增加文件身份与变更检查，拒绝缓存校验期间被修改的文件 |
| 离线断句 | 小数、版本号、域名的内部句点会被切开；长段上限多出 1 字符 | 保留内部句点，长段严格不超过 220 字符 |
| 引擎通信与隐私 | 原始异常堆栈、异常消息可能包含正文；依赖输出可能混入 JSON 协议 | 校验请求结构、丢弃请求执行中的 Python 级诊断输出，只保留明确编写的安全错误消息 |
| 本地网络防护 | 原防护仅包围翻译推理阶段 | 将健康检查与翻译的依赖初始化也纳入现有 Python socket 防护；明确的模型安装仍可联网 |
| 设置保存 | 固定临时文件名导致并发冲突；失败或取消可能留下临时文件 | 同一路径在进程内共享有界锁池，独立临时文件，同目录替换，发布前检查取消并清理失败文件 |
| 自定义翻译 | 空译文被当作成功；空 `choices`、畸形模型列表处理不一致 | 明确校验结构；空结果或畸形响应抛出稳定错误，让既有离线回退逻辑决定是否可回退 |

设置锁针对同一进程内的规范化路径，不是跨进程事务系统；权限错误仍会向调用方报告。Python socket 防护不是操作系统网络沙箱，Python 输出重定向也不能保证拦截所有原生库直接写文件描述符的行为。

## 合成文件内存测量

环境为 Linux、CPython 3.13.5。创建一个 128 MiB 合成文件，文件创建不计入测量；每次清空哈希缓存，两个实现交替各运行 3 次。用 `tracemalloc` 记录单次校验期间的 Python 分配峰值，以下为中位数：

| 实现 | 峰值 Python 分配 | 单次校验耗时 |
| --- | ---: | ---: |
| 基线 `read_bytes()` | 128.005 MiB | 0.1227 秒 |
| 固定缓冲区读取 | 1.005 MiB | 0.0857 秒 |

两种实现得到相同 SHA-256。该结果只衡量合成文件校验，不是整个软件的内存、OCR 准确率或翻译速度基准；耗时受文件系统缓存与设备影响。不得将峰值分配的下降比例宣传为整机内存或端到端速度改善。

## 自动化验证

新增 16 个 Python 测试方法，以及 36 个 .NET 测试用例（包括参数化用例）。Python 覆盖分块读取、空文件、缓存、文件替换/校验中修改、断句、协议恢复、隐私哨兵和联网边界；.NET 覆盖并发设置读写、取消、失败清理、畸形响应、空译文实际触发回退，以及段落保留。

```powershell
dotnet test PingYi.slnx
python -m unittest discover -s engine_host -p "test_*.py"
python -m unittest discover -s scripts -p "test_*.py"
```

实施过程中，新增 Python 测试在本地全部通过。首次双平台 CI 的 Ubuntu 构建与全部测试通过，Windows 的新增跨实例设置并发测试暴露 `File.Move` 冲突；后续修复改用同路径共享锁，而没有删除或跳过该测试。最终状态以本 PR 最新提交的 Windows、Ubuntu CI 为准。开发容器没有 .NET SDK，因此 .NET 编译与测试由仓库现有 GitHub Actions 执行。

## 合并与发布前的人工验收

仍需在 Windows 10/11 和 Ubuntu X11，用实际离线模型检查：断网冷启动与连续截图翻译；含版本号、小数、域名及长段的截图；本机大模型异常时的中英回退；快速修改设置、取消操作并重启后的设置一致性；非敏感测试样本触发异常时终端不出现正文。

模型质量测试、真实 GPU/CPU 推理、GUI 交互与安装包构建不属于本次已完成的本地验证。默认零历史记录、凭据存储和远程 HTTPS 限制保持不变。
