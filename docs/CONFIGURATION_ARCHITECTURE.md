# PingYi 配置架构（schema v15）

PingYi 将模型服务、模型目录、任务路由和运行环境分开管理。v0.8.4 及更早版本的单端点配置会在加载时迁移到兼容服务档案；不会要求重新下载模型或重新输入 API Key。

## 配置中心

设置新增“配置中心”页面，支持：

- 多个模型服务档案并存，每个档案有独立名称、类型、端点、协议、默认模型 ID、启用状态和能力声明。
- 服务商预设包括 OpenAI、DeepSeek、SiliconFlow、OpenRouter、阿里云百炼和智谱；也可以手动添加本地或自定义兼容端点。
- API Key 使用每个服务独立的 `credentialRef` 保存到系统安全存储。配置文件只保存引用，不保存密钥值。迁移的旧档案继续引用旧密钥条目，避免升级后丢失凭据。
- 服务测试调用模型列表接口并将模型 ID 缓存到中央模型目录。模型能力来自用户声明/服务配置，不会仅凭模型名称伪造视觉能力。
- OCR、翻译、图片描述、提示词反推可分别选择服务。二维码解码固定使用本地 ZXing。
- OCR 与翻译分别提供显式本地回退开关：OCR 回退 PaddleOCR，翻译回退 Argos。关闭后失败会直接报告，不会静默切换服务。

## 协议与兼容

- OpenAI 档案默认使用 Responses API；可切换 Chat Completions。
- DeepSeek、SiliconFlow、OpenRouter、DashScope、智谱和本机服务默认使用 Chat Completions。
- 本地服务必须使用回环地址；远程服务必须使用 HTTPS。
- Responses API 视觉请求使用 `input_image` 并设置 `store:false`。
- 本机 Vulkan/CUDA/ROCm/CPU 后端与现有模型安装管理保留。运行环境配置仍由原运行环境页面及兼容字段管理。

## 首次启动

首次启动向导现在提供：
- 下载并配置本地基础模型；
- 使用轻量模式；
- 连接已有本机模型服务（进入配置中心继续设置）；
- 配置第三方 API 混合模式：OCR 使用本地 PaddleOCR，翻译使用用户选择的云端模型。

云端向导要求用户输入模型 ID 和 API Key。密钥写入系统安全存储，远程翻译默认逐次确认后才发送识别文本。

## 数据传输与隐私

“隐私与安全”页提供“每次远程模型请求前都确认”选项，默认开启。远程翻译会发送识别文字；远程 OCR、图片描述和提示词反推会发送本次选中的截图。服务商可能记录、保留或计费；请查看其政策。二维码始终在本地解析。

## schema v15 迁移

- 旧 `CustomTranslationEndpoint`、模型 ID 和协议迁移到 `legacy-custom` 服务档案。
- 旧 API Key 不复制到 JSON；`legacy-custom` 的 credentialRef 指向原系统安全存储条目。
- 旧 OCR/翻译提供商选择迁移为独立任务路由。
- 旧 GPU 后端、设备、模型包和下载镜像配置同步到新的 runtime profile，同时保留原字段供现有运行时组件继续使用。
- 旧配置中没有独立服务的任务默认指向兼容档案；二维码路由迁移为 `builtin:qr`。

## 当前范围说明

本阶段已经实现配置模型、迁移、独立服务档案与密钥、模型目录缓存、任务路由、显式 OCR/翻译回退、配置中心、隐私确认和云端首次启动入口。GPU 安装器/设备选择仍沿用原运行环境页面；浏览器桥接和少数历史设置入口尚未全部切换到新任务路由模型，后续需要单独迁移和回归。
