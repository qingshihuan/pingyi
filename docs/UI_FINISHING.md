# Native desktop finishing pass

The main window uses a left-aligned capture action, concise copy and an original
static document/translation illustration. The existing mode switch is kept in a
separate compact processing section; model and privacy information remain real
status controls below it, not fabricated activity or history.

Settings use colored, project-authored sidebar glyphs and grouped label/value
rows. The first category splits recognition and translation preferences, with a
separate explanation of the data boundary. It preserves all named fields,
provider events, immediate-save behavior and the fixed Save/status area. The five
categories remain native TabItems, so their existing keyboard navigation works.

The finishing pass uses the existing Avalonia runtime, static gradients and
small shadows. It adds no blur, animation timer, web view, telemetry, font package
or image asset. Previously optimized engine startup, idle reclamation and OCR
scheduling files are untouched. Native Windows/Ubuntu title bars are kept; this
is a visual direction, not a claim of new macOS support.

The workspace prioritizes installed Chinese sans-serif families before Latin
fallback, including Microsoft YaHei and Noto Sans CJK SC. No font is downloaded by
the app or bundled by this change. Glyph appearance still depends on the host's
installed fonts; Windows Server CI images may lack the usual desktop CJK fonts.

## Verification

Run the existing Python structural tests and `dotnet test PingYi.slnx`. Additional
`NativeFinishingTests` check grouped preferences at the default size, unchanged
input across category switches, fixed Save controls, and capture actions at both
minimum and default sizes in both languages. Existing light/dark, result-card
and keyboard-navigation tests remain enabled. CI renders actual XAML; synthetic
preview data is explicitly labeled and is not an OCR/model quality measurement.

No release artifacts or user settings are generated by the design pass. Source
review artifacts contain only the exact tracked code, not local credentials,
font installations or model downloads.

Design references: Apple HIG Materials
(https://developer.apple.com/design/human-interface-guidelines/materials), used
for hierarchy and restraint rather than an imitation of Liquid Glass effects.
