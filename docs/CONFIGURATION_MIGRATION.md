# 统一模型配置迁移（schema 16，未发布）

## 执行前备份

配置继续使用现有用户目录及密钥存储机制，不新增强制凭据库。Windows 为 `%LOCALAPPDATA%/PingYiComplete`，Linux 为 `$XDG_CONFIG_HOME/pingyi-complete`（默认 `~/.config/pingyi-complete`）。升级前退出程序，备份 `settings.json`、已有备份和 `secrets/`；Linux 使用原有密钥服务时保留该服务中的条目。

首次保存旧配置前，程序按原始字节生成 `settings.json.pre-v16.bak`，不覆盖已有备份。读取配置本身不写盘；保存使用同目录临时文件和原子替换。较新版本或损坏配置不能被默认值静默覆盖。

## 转换原则

- 保留服务标识、地址、模型目录、快捷键、语言和后端设置；存储格式继续按地址保留本地与云端两个集合，界面统一在“API 模型管理”中编辑。本次页面合并不升级 schema，不搬迁或重写密钥。
- 翻译、截图识字、图片描述和提示词反推统一使用一个当前模型。原任务绑定不再执行。
- 只有文字与图片测试都通过的服务模型可被选中。旧配置未验证、绑定冲突或曾使用传统 OCR 时保留候选信息，提示重新验证和选择；不静默改发其他服务。
- 已下载的本地模型和推理后端不删除，重新验证后可以继续使用。旧 OCR/轻量模型文件也不在升级时删除，但新程序不加载它们。
- 旧自定义 API Key 只在目标地址一致且目标密钥为空时复制；原密钥保留。迁移不改写已有密钥，也不在输出中显示密钥。
- 新配置不再保存传统 OCR 引擎、轻量模式、任务独立绑定或离线回退开关。原始信息保留在用户本机备份中。

## 回退

退出程序，将升级后的配置另行备份后，用 `settings.json.pre-v16.bak` 恢复 `settings.json`，再运行原版本。密钥目录、模型和运行后端沿用原位置；不从 GitHub 获取或上传个人配置。仓库忽略配置、密钥目录、迁移备份及构建产物。

## 验证

迁移回归覆盖旧服务分流、模型能力限制、任务统一路由、密钥不覆盖、备份字节一致、损坏/未来版本拒绝覆盖、取消与并发保存。发布前检查暂存区、提交内容和打包目录中的敏感信息；本次重构不自动创建版本或 Release。
